# วางแผนดี ชีวิตมีเงินเก็บ (Savings Board Game)

## Overview
เกมกระดานดิจิทัลสอนวางแผนการเงินภาษาไทยสำหรับนักเรียน ม.ต้น สร้างจากบอร์ดเกมกระดาษ "วางแผนดี ชีวิตมีเงินเก็บ" — เลือกได้ 12/20/30 รอบ (ค่าเริ่มต้น 30) เล่นได้ 3 โหมด:
- **เล่นบนเครื่องเดียว (pass-and-play) 2–6 คน:** ส่งต่อจอเดียวกัน ไม่ต้องใช้เน็ตหลังโหลดหน้าแล้ว
- **ห้องออนไลน์กลุ่มเล็ก 2–6 คน (ผลัดตา):** สร้างห้อง แชร์ลิงก์ นักเรียนแต่ละคนเล่นจากมือถือตัวเอง กติกาตัดสินฝั่งเซิร์ฟเวอร์ (โกงจาก client ไม่ได้) หลุดเน็ตแล้วต่อกลับเข้าที่นั่งเดิมได้อัตโนมัติ
- **QR code เข้าห้อง:** สร้างห้องแล้วในล็อบบี้มี QR code ของลิงก์ห้อง (นักเรียนสแกนจากมือถือเข้าเล่นได้ทันที) + ปุ่ม "แสดง QR เต็มจอ" สำหรับฉายโปรเจกเตอร์ให้ทั้งห้องสแกนพร้อมกัน • QR generator เขียนเองแบบ self-contained ใน `qr.js` (byte mode, auto version, เลือก mask จาก penalty) ไม่พึ่ง CDN — ตรวจ matrix ตรงกับไลบรารี `qrcode` มาตรฐาน 100% (320/320 forced-mask + 40/40 auto ครอบคลุมทุกระดับ ECC/เวอร์ชัน) • ลิงก์ตัด `__raw` ที่แพลตฟอร์มเติมให้ iframe ออกเป็นลิงก์ห้องสะอาด
- **⚫ ตัวหมากปริศนาสีดำ (NPC):** เกิดกลางเกมตามความยาว (12 รอบ→เกิดรอบ 3, 20→รอบ 5, 30→รอบ 7) **ที่ช่อง START (ช่อง 0) เสมอ** (ไม่สุ่ม/ไม่ไปโผล่ตรงคนเล่น) รอบแรกแค่ปรากฏตัว จากนั้นเดินอัตโนมัติด้วยการทอยเต๋าตอนขึ้นรอบใหม่ — ใครอยู่ช่องเดียวกับมันเจอเหตุการณ์ไม่คาดคิด **ดี 30% (ได้เงิน 1,000–2,000) / ร้าย 70% (เสียเงิน 1,000–2,000)** เงินผ่านระบบ receiveCash/charge ปกติ • แจ้งเตือนป๊อปอัปทุกจอ • ตัวหมากสีดำเต้นตุบ ๆ บนกระดาน • ทั้ง 2 โหมด (ตรวจ 297/297 spawn ที่ช่อง 0)
- **เจ้าของห้อง (โหมดทั้งห้อง) = จอมอนิเตอร์ ไม่ลงเล่น:** สร้างห้องแล้วเป็นจอภาพรวมสำหรับครู/โปรเจกเตอร์ — เห็น **กระดานรวมว่าใครอยู่ช่องไหน** (ตัวเดินทุกคน) + **สถิติ** (จำนวนผู้เล่น, เงินออมรวม/เฉลี่ย, คนมีหนี้, อัตราตอบคำถามถูก) + **อันดับเศรษฐีเรียงตามเงินรวม** (savings+cash−debt มากสุดก่อน พร้อมช่องปัจจุบันของแต่ละคน) • เจ้าของห้อง sit ไม่ได้ (เซิร์ฟเวอร์บล็อก) แต่ยังคุมเกมได้ (config/begin/kick/reset/หยุดเกม/ดันเกมต่อเมื่อหมดเวลา) • ผู้ที่เข้าห้องแต่ไม่ได้นั่งเล่นก็เห็นจอมอนิเตอร์เช่นกัน • kernel maxPlayers=121 เผื่อ 120 นักเรียน + 1 มอนิเตอร์ (จำกัด 120 ให้ state อยู่ใต้ขีด 128KB ของแพลตฟอร์มอย่างมี margin — ห้องใหญ่ >50 คน ลดสมุดบัญชีต่อคน + ย่อผลรายรอบอัตโนมัติ)
- **หัวหน้าห้อง = ผู้สร้างห้องเสมอ** (คนแรกที่เปิดลิงก์) แม้นักเรียนกดเข้าร่วมก่อน และคุมห้องได้โดยไม่ต้องลงเล่น (จอผู้ชม) • เครื่องมือหัวหน้าห้อง: 🔄 รีเซ็ตห้อง (ในล็อบบี้และกลางเกม — คงโหมด/จำนวนรอบ ทุกคนกดเข้าร่วมใหม่), ❌ เชิญผู้เล่นออก (ในล็อบบี้), 👑 มอบตำแหน่งหัวหน้าให้คนอื่น
- **ปิดแท็บ/เบราว์เซอร์แล้วกลับเข้าร่างเดิมได้** — บัตรประจำตัวผู้เล่นเก็บใน localStorage ประจำเครื่อง (ครูได้ตำแหน่งคืน นักเรียนได้ที่นั่ง/เงินคืน) • ถ้าเครื่องหัวหน้าพังถาวร: หัวหน้าที่ออนไลน์ส่ง ping ทุก 45 วิ ถ้าเงียบเกิน 1.5 นาที ผู้เล่นในห้องกด "🆘 ขอเป็นหัวหน้า" รับตำแหน่งแทนได้ (หัวหน้ายังอยู่ = เซิร์ฟเวอร์ปฏิเสธ) — ห้องไม่มีทางค้างถาวร
- **โหมดทั้งห้องสไตล์ Kahoot 2–120 คน (ค่าเริ่มต้นของห้องออนไลน์):** ทุกคนทอยพร้อมกัน (20 วิ ไม่กด = ทอยอัตโนมัติ) แล้วตอบคำถาม/ตัดสินใจของตัวเอง 40 วิ (หมดเวลา = คำถามสุ่มตอบ เงินรายรับออมครึ่งอัตโนมัติ) ขึ้นรอบพร้อมกันทั้งห้อง มือถือนักเรียนแสดง **กระดานเศรษฐี 23 ช่องพร้อมตัวเดินของตัวเองวิ่งรอบ (อนิเมชันเดินทีละช่อง + ทอยเต๋าตรงกลาง)** + ตำแหน่งปัจจุบัน/ผลรอบนี้/เงิน/อันดับ/ประวัติกิจกรรม (ไม่โชว์รายละเอียดการเล่นของคนอื่น) ส่วนคนที่ไม่ได้นั่ง (ครู) เห็นจออันดับสดไว้ฉายโปรเจกเตอร์ • หัวหน้าห้องสลับโหมดในล็อบบี้
  - **ป๊อปอัปเหตุการณ์ 2 จังหวะ:** (1) ตอน**ตกลงช่อง** เด้งบอกว่าเจอช่อง/เหตุการณ์/โอกาสอะไร (การ์ดพลิก + ไอคอน) + ถ้ามีการตัดสินใจจะบอกใบ้ให้ตอบด้านล่าง (2) ตอน**ตอบคำถาม/ตัดสินใจเสร็จ** เด้งอีกครั้งบอกผล (ถูก/ผิด + เฉลย, กำไร/ขาดทุน) — เฉพาะช่องที่มีการตัดสินใจ • ปิดเองใน 5 วิ หรือกด "ไปต่อ" • ผูกกับ "การทอยครั้งนั้น" (lastRoll.r) ไม่ใช่รอบปัจจุบัน กันกรณีผู้เล่นตัดสินใจคนสุดท้ายแล้วรอบเลื่อนทันที (ทดสอบกับเซิร์ฟเวอร์จริง: ตกลงช่องเด้งครบทุกรอบ, ผลเด้งเฉพาะรอบที่มีตัดสินใจ, ไม่ซ้ำ)
  - เทคนิค: broadcast บ่อย (50 คน × ทุก action) → กระดานถูกสร้างครั้งเดียวและอยู่ถาวร อัปเดตเฉพาะตัวเดิน/ลูกเต๋า, พาเนลข้อมูลวาดใหม่เมื่อ signature เปลี่ยน (กันปุ่มตัดสินใจถูกรีเซ็ต), มี safety ปลดล็อกอนิเมชันเองใน 3.5 วิ กันค้างเมื่อเครื่องช้า

แก้ปัญหา: ทำให้การสอนเรื่องการออม เงินสำรองฉุกเฉิน การแยก "จำเป็น/อยากได้" และความเสี่ยงการลงทุน เป็นกิจกรรมสนุกที่เล่นซ้ำได้ พร้อมเก็บข้อมูลการเล่นอัตโนมัติ (ไม่ต้องจดกระดาน)

**เล่นออนไลน์:** https://elegant-gnome-812.higgsfield.gg/

### กติกาหลัก
- เริ่มเกมทุกคนได้เงินสด 5,000 บาท ทอยเต๋าเดินบอร์ด 22 ช่อง (ตามภาพต้นแบบ)
- ทุกรายรับเลือกได้ว่าแบ่งไป "เงินออม" เท่าไหร่ • เดินครบรอบบอร์ดรับดอกเบี้ยเงินออม 10% (สูงสุด 2,000)
- เงินสดไม่พอจ่าย → ถอนเงินออมเสียค่าธรรมเนียม 10% → ยังไม่พอ = เป็นหนี้
- ช่องเงินสำรองฉุกเฉินให้ "โล่" กันเหตุการณ์ร้าย 1 ครั้ง • ตอบคำถามความรู้การเงินระดับ ม.ต้น (30 ข้อ รวมเรื่องเติมเกม/กล่องสุ่ม ไลฟ์ขายของ พนันออนไลน์) ถูกรับโบนัส 1,000
- ครบทุกรอบ: เงินออมมากสุด + ไม่มีหนี้ = ผู้ชนะ

### ระบบจัดเก็บข้อมูล
- **สมุดบัญชี (กระดานผู้เล่น):** บันทึกทุกธุรกรรมอัตโนมัติ (รอบ/ผู้เล่น/รายการ/ยอดคงเหลือ) เปิดดูในเกม + ดาวน์โหลด CSV (เปิดใน Excel ได้ มี BOM UTF-8) — มีทั้ง 2 โหมด
- **เซฟอัตโนมัติ (โหมดเครื่องเดียว):** localStorage — ปิดเบราว์เซอร์แล้วกด "เล่นต่อจากเกมค้างไว้" ได้
- **ประวัติ & สถิติ:** เก็บผล 50 เกมล่าสุด สถิติเงินออมสูงสุด อัตราตอบคำถามถูก — บันทึก**ทุกโหมด** (เครื่องเดียว + ออนไลน์กลุ่มเล็ก + ทั้งห้อง) ลง localStorage เดียวกัน `wangplandee.history.v1` ตอนจบเกม • โหมดออนไลน์มีปุ่ม "📊 สถิติ" ในหน้าจบเกม (บันทึกลงเครื่องที่เปิดดู เช่น เครื่องครู)

### เสียง (กันเสียงตีกันในห้องเรียน)
เสียงทั้งหมด**สังเคราะห์ด้วย WebAudio** ใน `sound.js` (ไม่มีไฟล์เสียง/CDN) — เพลงพื้นหลังลูป (เพนทาโทนิก) + เอฟเฟกต์ (ทอยเต๋า/ตกช่อง/ได้เงิน/เสียเงิน/ตอบถูก-ผิด/ป๊อปอัป/ชนะ). **นโยบายกันเสียงเหลื่อมกัน** (แบบ Kahoot): จอมอนิเตอร์/ครู (ต่อลำโพงหน้าห้อง) เปิดเพลง+เอฟเฟกต์เป็นค่าเริ่มต้น • มือถือนักเรียน**ปิดเสียงเป็นค่าเริ่มต้น** (เปิดเองได้ด้วยปุ่ม 🔊 ถ้าเล่นที่บ้าน) • โหมดเครื่องเดียว/กลุ่มเล็กเปิดทั้งคู่ • จำค่าเปิด/ปิดแยกตามบทบาทใน localStorage • ปลดล็อก AudioContext ด้วยการแตะครั้งแรก (นโยบาย autoplay)

## Getting Started

**รันเซิร์ฟเวอร์เอง (แนะนำ — เล่นออนไลน์ได้ครบทุกโหมด ไม่ต้องพึ่ง Higgsfield):**
```bash
cd savings-game
npm install          # ติดตั้ง ws (ครั้งแรกครั้งเดียว)
npm start            # = node server.js  (พอร์ตเริ่มต้น 3000; PORT=8080 npm start เพื่อเปลี่ยนพอร์ต)
# เปิด http://localhost:3000/  → กด "สร้างห้องออนไลน์" → แชร์ QR/ลิงก์ ?room=... ให้ทุกคน
```
`server.js` แทน "kernel" ของ Higgsfield: เสิร์ฟไฟล์ static ใน `public/` + จัดการห้อง WebSocket (`/ws/<room>`) + ขับ `logic.js` (setup/validate/apply/viewFor). ในห้องเรียน: รันบนเครื่องครู นักเรียนสแกน QR เข้า `http://<LAN-IP>:3000` ในวง WiFi เดียวกัน (เซิร์ฟเวอร์พิมพ์ LAN IP ให้ตอนเริ่ม) — ฟรี ไม่ต้องใช้อินเทอร์เน็ต

ขึ้น cloud สาธารณะ (ได้ลิงก์ https): push โฟลเดอร์นี้ขึ้น Render/Railway/Fly.io แล้วตั้ง start command = `node server.js` (ใช้ `process.env.PORT` อัตโนมัติ)

**โหมดทดสอบเครื่องเดียว (ไม่ต้องใช้ server):**
```powershell
python -m http.server 8734 -d savings-game/public   # เปิด http://localhost:8734
```

ทดสอบออนไลน์:
- **บอท ws นอกเบราว์เซอร์:** `scratchpad/smoke.mjs` (คัดลอกเข้าโฟลเดอร์ savings-game แล้ว `node smoke.mjs` — ต่อ `ws://localhost:3000`) ตรวจ flow join→sit→begin→roll ทั้ง 2 โหมด
- **ปุ่ม ➕ เพิ่มบอทในล็อบบี้ (โหมด dev):** เปิดลิงก์ห้องพร้อม `&dev=1` → ในล็อบบี้ (ฝั่งหัวหน้าห้อง) จะมีปุ่ม "🤖 เพิ่มบอท" กดเพื่อเพิ่มบอทที่เล่นเองอัตโนมัติเข้าห้อง (ทดสอบเกมคนเดียวได้ทั้ง 2 โหมด) • ลบด้วยปุ่ม 🗑️ หรือเตะด้วย ❌ • โค้ดใน `public/botclient.js`
- **สคริปต์ Node (นอกเบราว์เซอร์):** `test/run-test.mjs` สร้างหัวหน้า+ผู้เล่นบอท N คนเล่นจนจบแล้วสรุปอันดับ, `test/bot.mjs` รันบอทเดี่ยว — ใช้ WebSocket ในตัวของ Node 21+ (ดู `test/README.md`) • ต้องรันกับ URL ที่ deploy แล้ว

## Project Structure
```
savings-game/
├── server.js          # เซิร์ฟเวอร์ self-host: HTTP static + WebSocket kernel (แทน Higgsfield) ขับ logic.js
├── package.json       # type:module, dep: ws, `npm start` = node server.js
├── public/            # เนื้อหาฝั่ง client ทั้งหมด (server.js เสิร์ฟจากที่นี่ / เดิมเป็น root ของ zip)
│   ├── index.html     # โครงหน้า 5 จอ: เมนู/ตั้งค่า/เกม/สรุปผล/ล็อบบี้ออนไลน์
│   ├── game.js        # โหมดเครื่องเดียว + เซฟ/โหลด • มี ?room= จะส่งต่อให้ online.js
```
